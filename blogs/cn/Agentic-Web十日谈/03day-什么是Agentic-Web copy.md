# Agentic Web 十日谈·第三日：什么是 Agentic Web？当智能体成为互联网的第一公民

> 最近比较忙，上一篇和这一篇之间隔的时间有点长。不过会坚持写完。

> **核心问题**：如果互联网的主要用户不再是"人"，而是"智能体"，这个网络会变成什么样子？

前两日,我们回顾了 Web 封闭化的历史,推导出智能体作为新的执行主体,需要一个开放的互联网环境来获取上下文和执行能力。

很多人会问:"你说的 Agentic Web(智能体互联网),不就是现在的互联网加上 API 吗?"

答案是否定的。

**Agentic Web 不是对现有互联网的修补。** 就像移动互联网不只是"PC 互联网 + 手机",它带来了位置服务、永远在线、触控交互等新范式。

Agentic Web 同样带来三个变化。在讨论这些变化之前,我们先给它一个清晰定义。

---

## 一、定义 Agentic Web

如果用一句话来定义 Agentic Web:

> **Agentic Web 是一个以智能体(Agent)为主体,以标准协议为核心,以开放协作为基本形态的新一代互联网。**

这里有三个关键词:

1.  **互联网主体(Internet Subject)**:从"人"变为"智能体"。
2.  **协议为核心(Protocol-Centric)**:从"UI"变为"协议"。
3.  **开放协作(Open Collaboration)**:从"数据孤岛"变为"开放连接"。

这听起来有些抽象?让我们通过三个具体的转变来拆解它。

---

## 二、转变一:从"人看网页"到"智能体办事"

**当下的互联网,更像一场注意力竞争。**

无论是新闻网站、社交媒体还是电商平台,它们的设计目标都是争夺人类的注意力。界面越来越精美,交互越来越上瘾,算法越来越懂你的偏好。

在这一层面上,智能体多半是辅助工具,帮你总结网页、帮你生成回复。**人,依然是网络的主体。**

**Agentic Web 更看重"任务完成"。**

在 Agentic Web 中,访问网络的主体不再是人类,而是代表人类意图的智能体。

-   **人类访问**:浏览页面 → 理解信息 → 点击按钮 → 完成任务(比如买一张票)。
-   **智能体访问**:接收意图 → 发现服务 → 协商参数 → 执行交易(比如直接调用订票协议)。

当智能体成为"第一公民",互联网的评价标准也会变化:
从"页面停留时长"(Time on Site)变成"任务完成率"(Task Completion Rate);
从"日活用户数"(DAU)变成"日服务调用量"(Service Calls)。

**智能体不再只是工具,而是直接办理事务的角色。**

> **【插图概念提示】**
>
> **画面描述**:
> 左侧是"Human Web":一个人面对着无数闪烁的屏幕(网页、App),屏幕上满是弹窗、广告和鲜艳的按钮,试图抓住人的注意力。
> 右侧是"Agentic Web":一个智能体面向清晰的管道和接口,直接连接"支付""物流""日历"等功能模块。没有广告,没有干扰,只有有序流动的数据。
> **核心隐喻**:左边是迷宫,右边是直达通道。

---

## 三、转变二:从 UI 驱动走向协议驱动

既然用户从"人"变成了"智能体",连接方式也必须改变。

今天,当你想让智能体帮你订餐时,现有的解决方案(如 Computer Use 或 Browser Use)仍在模拟人类操作:
1.  打开浏览器
2.  输入网址
3.  等待页面加载(包括广告)
4.  识别哪个是"预订"按钮
5.  模拟鼠标点击

**这是一种低效且脆弱的过渡方案。** 网页改版、按钮移位、弹窗广告,任何微小的 UI 变化都可能让任务失败。

**在 Agentic Web 中,协议取代 UI 成为核心。**

服务提供商不再只提供 HTML 网页,而是提供标准的**智能体描述协议(Agent Description Protocol)**。
-   不需要告诉智能体"这是一个红色按钮,上面写着预订",
-   而是直接通过协议告诉它:`Function: book_table(time, pax, requirements)`。

UI 面向人类,需要视觉反馈和情绪引导;
协议面向机器,需要结构化数据和确定性逻辑。

**未来的互联网将分化为两层:**
1.  **表层(Human Layer)**:依然保留精美 UI,供人类娱乐、社交、体验。
2.  **里层(Agent Layer)**:基于标准协议的能力网络,供智能体交换数据、执行任务。

**Agentic Web,就是这个正在形成的"里层"。**

> **【插图概念提示】**
>
> **画面描述**:
> 对比图。
> 上半部分:智能体通过网页解析来理解服务,步骤繁琐、容易出错。
> 下半部分:智能体直接连接服务接口,返回整齐的 JSON/XML 结构块,处理快速而稳定。
> **核心隐喻**:从"看界面"到"读结构"。

---

## 四、转变三:从平台封闭走向开放协作

这是最难的转变。

现在的互联网是"平台化"的。超级 App(Super Apps)希望把所有服务都圈在自己的围墙里:你想打车?用我的。想点外卖?用我的。想看电影?还在我的 App 里。

这种模式对人类来说虽然臃肿,但尚可接受;对智能体来说则明显受限。

**智能体天生需要"组合"能力。**

想象一个场景:**"帮我策划一次去日本的旅行。"**

在封闭网络中,没有一个 App 能独立完成这个任务:
-   旅游 App 能订票,但不知道你的日程(在日历 App 里)。
-   日历 App 知道时间,但无法支付(在银行 App 里)。
-   银行 App 能支付,但不懂你的攻略偏好(在社交 App 里)。

在 Agentic Web 中,连接形态是**去中心化协作**:

用户的"私人助理智能体"不需要自己拥有所有能力,它可以动态发现并连接其他专精智能体:
1.  呼叫**"旅行规划智能体"**生成路线。
2.  "旅行规划智能体"请求**"日历智能体"**确认空闲时间。
3.  确认后,调度**"机票预订智能体"**和**"酒店预订智能体"**下单。
4.  最后调用**"支付智能体"**完成结算。

这些智能体可能属于不同公司,甚至是个体开发者,但它们通过通用的**智能体通信协议(Agent Communication Protocol)**协作。

**这不再是"一个个孤岛",而是可拼装的能力网络。**

> **【插图概念提示】**
>
> **画面描述**:
> 左侧:几个巨大的封闭堡垒(代表巨头平台),堡垒之间有深沟高墙,互不相通。
> 右侧:无数个大小不一的节点(代表各种 Agent),它们之间通过发光的线条(协议)自由连接,形成一张大型网状结构。某个任务触发时,一条路径迅速点亮多个节点。
> **核心隐喻**:从"帝国割据"到"协作网络"。

---

## 五、为什么这不仅仅是技术升级?

理解了上面三个转变,你就会明白为什么我们说 Agentic Web 是"连接目标的回归"。

Tim Berners-Lee 创造万维网的初衷,就是为了"连接"。
-   Web 1.0 连接了文档。
-   Web 2.0 连接了人。
-   **Agentic Web 将连接服务和行动。**

当智能体能够跨越平台围墙,在网络中顺畅流动;
当服务能力像电力一样,通过标准插座(协议)即插即用;
当每一个微小的开发者,都能通过协议被全球智能体发现并调用。

我们将看到的,不只是效率提升。

---

## 结语:理想很丰满,现实很骨感

"听起来很美好,但巨头们会答应吗?"

这是很多人在听到 Agentic Web 构想时的第一反应。

确实,现有互联网巨头依靠封闭生态赚取了巨额利润。让他们开放接口、打破围墙,无异于与虎谋皮。

**冲突已经开始。**

2024 年末至 2025 年初,我们目睹了智能体生产力与旧生产关系的第一次剧烈碰撞:豆包手机助手被封杀事件。

这不仅仅是一个商业纠纷,这是一个信号:**当新的执行主体试图在旧的生产关系中穿行时,必然会擦出火花。**

下一日,我们将深入剖析这次事件:**《第四日:第一次正面碰撞——豆包手机助手与旧互联网生产关系》**。
