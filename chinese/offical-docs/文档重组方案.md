# ANP 文档结构重组方案

## 对标 MCP 的文档结构

根据 MCP 官网的文档组织方式,ANP 文档应该采用以下三层架构:

```
ANP 官网
├── Documentation (文档) - 面向开发者的实用指南
├── Specification (规范) - 协议技术规范
└── Community (社区) - 治理和贡献
```

## 优势分析

### 1. 清晰的信息架构
- **Documentation**: 实用导向,帮助开发者快速上手
- **Specification**: 规范导向,提供权威技术细节
- **Community**: 社区导向,促进协作和治理

### 2. 渐进式学习路径
- Get Started → About ANP → Develop with ANP
- 从概念到实践,循序渐进

### 3. 模块化组织
- 按功能模块分类(身份、描述、发现、支付)
- 每个模块独立完整,便于维护

### 4. 版本化规范
- `specification/2025-01-17/` 支持多版本共存
- 方便协议演进和向后兼容

### 5. SDK集成
- 将SDK文档整合到官网
- 提供统一的开发者体验
