# ANP-05 实现验证指南

- 状态：资料性验证指南；对应尚未发布的协议草案
- 协议基线：[ANP-05 v0.7](../../chinese/05-ANP-基于DID的授权协议.md)
- Profile：OAuth `anp.authorization.oauth2.cimd.v1-draft1`；VC `anp.authorization.vc.v1-draft2`
- 英文镜像：[Implementation Validation Guide](../anp-05-validation-guide.md)

本指南收录从 ANP-05 提取的实现验证场景。协议要求与一致性规则以协议正文为准，尤其是[第 14 节](../../chinese/05-ANP-基于DID的授权协议.md#conformance)。下方场景中的章节编号均指协议正文。

## 验证场景

以下是设计场景，不是宣称某个实现已经通过。根据所声明的角色和能力验证适用的正向流程及全部相关拒绝路径；未实现的可选能力应记录为不支持，不能报告为通过。本指南不记录 JWT/VC 签名验证、端到端授权或互操作测试的实际执行结果。

对 OAuth，记录在每次流程开始前选定的处理模式。`cimd` 使用标准 CIMD 授权服务器，不要求该服务器提供 ANP 元数据、解析 DID 或验证 DID 绑定；`did_bound` 增加 ANP 绑定检查，声明 `anp_cimd_binding` 的 AS 对所覆盖端点接受的 CIMD 客户端强制执行这些检查。记录为算法、断言 audience/type、回调处理、资源指示和混淆攻击防护选定的 AS 能力与策略；必需检查失败后不得改用较弱配置重试。标记为 `did_bound` 的场景不对未声明该扩展的普通 CIMD 服务器施加该要求。VC 场景和 Profile 保持独立且不变。

| ID | 场景与预期结果 |
| --- | --- |
| AUTHZ-01 | `did_bound` 中，已批准 CIMD URL 客户端、通过方法验证的 `did:wba` 文档、已验证 URL/元数据/密钥绑定及客户端凭据策略：签发目标受限令牌。对每种已声明支持的 DID 方法重复此正向流程。 |
| AUTHZ-02 | `did_bound` 中，已批准且关联 WBA 的 CIMD 客户端：仅在声明的 WBA 绑定与当前 OAuth 密钥授权通过后签发。 |
| AUTHZ-04 | 用户批准的授权码，重定向、state/会话与 S256 PKCE 匹配：保留用户主体和资源。 |
| AUTHZ-05 | 错误签名、`none`/`HS*`、不兼容算法或不支持曲线：拒绝。 |
| AUTHZ-06 | `did_bound` 中，本次实际签名密钥不在 `authentication` 或 `anp_oauth_keys`、DID 文档 `id` 错误或 JWS 头注入验证密钥：拒绝。`kid` 标签本身不能建立 DID 密钥授权。 |
| AUTHZ-07 | 请求 `client_id`、CIMD `client_id`、获取 URL 与断言 iss/sub 不一致：拒绝。拒绝不符合预先选定 AS 策略的 audience/type；只有该策略明确接受相应标准惯例时，才可采用令牌端点受众。 |
| AUTHZ-08 | 本 Profile 生成的断言使用整数时间且满足 `0 < exp - iat <= 300`；按选定验证方策略拒绝过期、时间过于超前或 NumericDate 格式错误的断言。`did_bound` 要求第 6.1 节全部声明，执行其中的时间/偏差边界，并拒绝非整数 `nbf`、`nbf > exp` 或 `nbf > now + skew`。 |
| AUTHZ-09 | `did_bound` 中复用或并发提交一个 `jti`，包括更换密钥/服务器副本：最多接受一次认证。普通 CIMD 防重放控制须满足部署预先选定的保证要求。 |
| AUTHZ-10 | 有效 DID 证明但准入未通过或没有权限，或尝试以客户端自身权限读取用户资源：不授予该访问权限。 |
| AUTHZ-11 | 授权码错误/复用、回调或 PKCE 不匹配、scope/resource 扩大，或他人客户端的刷新令牌：拒绝。 |
| AUTHZ-12 | 当前状态检查发现 CIMD 密钥已移除时，不得新认证；`did_bound` 中，旧解析结果刷新失败、DID 停用或 DID 密钥授权移除也失败。身份/URL 迁移不得自动继承授权。 |
| AUTHZ-13 | DID/元数据/context 获取、重定向或 DNS 重绑定引发 SSRF：阻止且不得签发令牌。生产环境获取 CIMD 及其包含的 URL 时拒绝特殊用途 IP 目标；draft-02 唯一例外是 AS 自身位于同一 loopback 接口的开发/测试。允许 loopback 回调不授权获取该地址。 |
| AUTHZ-14 | 将客户端断言当资源令牌、替换为 ANP-02 缓存令牌或 AS/RS audience 错误：拒绝。 |
| AUTHZ-15 | 授权撤销或刷新令牌复用时，按生命周期策略阻止签发/刷新。执行前按文档化新鲜度检查适用的撤销/状态；必需检查无法完成时不得视为已批准。 |
| AUTHZ-16 | 表单/JSON 安全字段重复或同时使用多种认证方式：拒绝歧义解析。 |
| AUTHZ-17 | 要求 DPoP 时，proof/密钥/token hash 错误或降级 Bearer：拒绝。 |
| AUTHZ-18 | 不支持的处理模式，或要求 `did_bound` 时 `anp_cimd_binding` 声明的 Profile 修订错误：拒绝，不更换客户端身份或降低认证强度；普通 `cimd` 不要求该扩展。 |
| AUTHZ-20 | 受保护资源元数据指向其他资源，或 AS 元数据 issuer 不匹配：在发送凭据前停止。 |
| AUTHZ-21 | `did_bound` 授权码处理要求 RFC 9207。选用 RFC 9207 时，授权响应（包括错误响应）的 `iss` 缺失、重复或不匹配：在兑换授权码前拒绝。普通 AS 不支持该能力时须预先选定文档化混淆攻击防护，issuer 验证失败不能触发较弱防护。 |
| AUTHZ-22 | 授权码兑换或刷新更改已授权资源、缺少预先选定 AS 约定要求的资源指示，或复用其他 AS/租户的客户端记录或令牌：拒绝。`did_bound` 要求 RFC 8707，且授权、客户端凭据、授权码兑换和刷新请求均明确携带 `resource`。普通 AS 支持的单资源绑定不必要求每次请求都携带 `resource`。 |
| AUTHZ-23 | 向 B 出示面向 A 的入站令牌：拒绝；独立获准且面向 B 的令牌成功。 |
| AUTHZ-26 | 仅因公共客户端持有密钥或使用 PKCE，就将其视为机密客户端：拒绝该客户端凭据配置。 |
| AUTHZ-27 | 只在可信 RS/AS 上下文中接受 scope 挑战，并重新批准、限制重试；挑战不能静默提升权限。 |
| AUTHZ-29 | 启用自发布准入，未知 CIMD URL 具有有效元数据/客户端证明及独立获准授权：无需预存客户端记录或注册 API 调用即可签发；`did_bound` 还验证 DID 关联。 |
| AUTHZ-30 | 关闭首次接触准入、策略拒绝，或已禁用客户端在缓存淘汰后重新登记：拒绝，不绕过当前身份或策略检查。 |
| AUTHZ-31 | CIMD 响应重定向，或 CIMD/JWKS 响应超限、重复安全字段或格式无效：签发 code/token 前拒绝。`did_bound` 中，`ANPCIMD` service 缺失/歧义、DID 回链错误、摘要缺失或密钥未获授权也失败；有效标准 JWKS 是正常输入。 |
| AUTHZ-32 | 授权端点发现只建立候选，兑换时检查客户端证明；已批准回调/认证/授权元数据变化导致未完成 code 失效。`did_bound` 还保留并重新核对 DID service、摘要与密钥授权快照。 |
| AUTHZ-33 | 元数据列出高权限 scope 或 client_credentials：不得视为资源授权；刷新仍须有效授权令牌绑定。 |
| AUTHZ-41 | `did_bound` 中，元数据托管方修改名称、回调、授权类型、密钥或序列化，却未更新已验证 DID 内摘要：在展示、回调或签发前拒绝；摘要缺失或格式错误同样失败。普通 CIMD 不宣称具有该 DID 摘要固定的完整性保证。 |
| AUTHZ-42 | 已批准原生 loopback 元数据、临时请求端口及精确兑换 URI 可以成功；主机/路径错误、兑换时换端口、未启用模式或非 native 应用均失败。 |
| AUTHZ-43 | 本机回调不授权 AS 获取 loopback/私网元数据；监听局域网或全部接口的配置不属于此绑定。 |
| AUTHZ-44 | `did_bound` 中，轮换 e1_ 获准运行密钥但保留绑定密钥/DID 与 CIMD URL，同步更新 `anp_oauth_keys`、JWKS 和元数据摘要：仅按策略保留授权并拒绝已移除密钥；DID 或 CIMD URL 改变不自动继承授权。 |
| AUTHZ-45 | 按预先选定的 AS 约定检查断言 typ/audience，使用一个精确 AS 受众和双方接受的客户端认证类型；仅在支持时选择 issuer-only 受众及显式 `client-authentication+jwt`。两种模式都不得在拒绝后按较弱选择重试。 |
| AUTHZ-46 | AS 已验证令牌或活动查询的 client_id 标识 CIMD URL 客户端，sub 标识用户；只有已验证绑定中的 DID 可受信，调用方注入声明或未验证回链不得替代；非活动查询结果不披露身份。 |
| AUTHZ-47 | 同一 Agent 为两个资源分别获得用户授权；选择令牌须包含用户/issuer/resource，拒绝跨资源或跨 AS 的账户/权限替换。 |
| AUTHZ-48 | 服务要求高风险操作批准时，缺失、不匹配或已消费的操作批准阻止执行；登录、宽泛 scope、DID/DPoP 证明本身不能满足该策略。 |
| AUTHZ-49 | 拒绝预先选定 AS 能力与策略之外的算法/曲线；`did_bound` 执行其声明的 DID 方法规则，包括拒绝不支持的 WBA 绑定。`cimd` 不因 ANP 示例采用 Ed25519 就要求该算法或任一 DID 方法。 |
| AUTHZ-50 | 仅客户端凭据部署不宣称用户委托；路线图中的转委托/逐笔批准/累计预算不能仅靠元数据声明就变成已启用能力。 |
| AUTHZ-53 | 凭证证明错误、签名密钥不在签发方 `assertionMethod`、VP 密钥不在持有者 `authentication`、签发方 DID 无法验证、未启用的密码套件或允许列表外的 context：拒绝。 |
| AUTHZ-54 | 凭证未生效或已过期、状态为撤销或暂停、状态列表签发方不同、状态列表缺少 `validUntil` 或已过期，或状态列表无法取得：拒绝，不视为有效。 |
| AUTHZ-55 | 签发方 DID 无法确认为对该资源有权的本地主体，或 Agent 自签委托（签发方等于持有者）：拒绝；凭证不能建立账户对应关系，签发资格只来自验证方本地绑定或信任策略。 |
| AUTHZ-56 | 请求资源不在凭证中、动作超出凭证或本地策略、存在不理解的约束，约束无法交给 RS 执行，或 `perOperationLimit` 的币种不同、操作没有文档化金额：拒绝；获授权限为三方交集。 |
| AUTHZ-57 | 直接出示时 challenge 缺失、过期或已用，`domain` 指向其他验证方，ANP-02 已认证 DID 与 holder 或事务中的请求方不同，请求的操作与出示事务中保存的不同，或把 `mode` 为 `operation` 的出示用于建立会话：拒绝，不执行操作。 |
| AUTHZ-59 | 把原始 VC 或 VP 放入 `Authorization` 头访问 RS，或在本 Profile 下向 OAuth 令牌端点提交 VC/VP：拒绝或不发送。 |
| AUTHZ-60 | Agent A 持有用户的委托但没有独立签发资格，给 Agent B 签发一份密码学上有效的委托凭证（转委托）：本版拒绝。 |
| AUTHZ-61 | 组织签发的角色凭证，签发方已被确认为验证方认可的组织，请求的操作按文档化对应关系落在所列动作与约束之内：接受，本次操作的主体为该组织的本地账户。 |
| AUTHZ-62 | 角色凭证含有验证方没有对应关系的动作 URI，或请求的操作不在任何所列动作之内，或超出单笔上限：拒绝该项或该操作。 |
| AUTHZ-63 | 签发方 DID 无法确认为验证方认可的组织，或验证方策略要求的组织身份凭证缺失、不受信：拒绝；仅凭 `role` 名称或 did:web 域名不能通过。 |
| AUTHZ-64 | 仅凭角色凭证、缺少资源方独立确认的有效访问依据就读取第三方个人数据，或代替高风险操作的逐笔批准：不能满足，拒绝或转入验证方自己的批准机制。 |
| AUTHZ-65 | 直接出示正向流程：经承载接口认证的请求方 DID、VP holder 与授权凭证 credentialSubject.id 一致，签发方权限、状态与约束有效；替换其中任何一个 DID 时拒绝。 |
| AUTHZ-66 | VP 的 domain/challenge 与保存的出示事务不符，challenge 过期、复用或并发消费：拒绝；并发出示至多接受一次。 |
| AUTHZ-67 | 委托凭证已撤销、暂停或过期，状态列表缺失、过期或无法验证：拒绝直接操作，并在状态复查发现后停止基于该凭证的会话。 |
| AUTHZ-68 | 直接出示只执行保存的操作，并执行权限求交与 5000 CNY 单笔上限；金额超限、币种不同、缺少金额、扩大动作或未知约束：拒绝。 |
| AUTHZ-69 | 出示请求缺少 profile 或版本不受支持：不签署 VP，不静默降级；VC/VP 不能绕过 OAuth 专用接口，也不能在本 Profile 下换发访问令牌。 |
| AUTHZ-70 | 出示事务只接受委托凭证，但收到角色凭证，或授权凭证具有两种 ANP 授权类型：即使类型分别受本 Profile 支持也拒绝替代。 |
| AUTHZ-71 | 会话建立后仅出示会话引用，或后续请求认证的 DID 不等于绑定 holder：拒绝该请求，不将引用视为身份或访问凭据。 |
| AUTHZ-72 | 5000 CNY 限额的会话先接受 4200 CNY 订单，后续 6000 CNY 订单、币种不符、对象/动作超范围或无法执行约束时仍须拒绝；不得复用首次操作的批准。 |
| AUTHZ-73 | 会话到期超过本地上限或凭证有效期，使用时自动滚动延长，或续期未重新出示新 challenge 绑定的 VP：拒绝该创建、延长或续期。 |
| AUTHZ-74 | 只出示资质或属性凭证而没有本 Profile 要求的委托/角色授权凭证：拒绝，即使该资质签名和签发方可信也不构成本版独立出示流程。 |
| AUTHZ-75 | 资源方已独立确认企业账户具有相应个人数据访问权限，且角色出示通过其余类型、身份、权限与约束检查：可按该依据与接口策略放行；缺少有效访问依据时拒绝。 |
| AUTHZ-76 | 标准 `cimd` 流程可在声明 CIMD 与 `private_key_jwt`、且双方支持签名算法的服务器成功，不要求 `anp_cimd_binding`、DID 解析器、`anp_profile`、`anp_application_type` 或必需的 `anp_did`；结果不宣称 AS 验证了 DID。 |
| AUTHZ-77 | 请求 `client_id`、断言 iss/sub、CIMD `client_id` 与最终元数据 URL 是同一 HTTPS 字符串。DID client_id、拼写不一致、3xx 响应或未获授权的替换 URL 均失败，不通过跟随重定向修复不一致。 |
| AUTHZ-78 | `did_bound` 中，复制受害者公钥到另一 DID、添加自声明 `anp_did` 或仅一端指向另一端，均不能建立受害者绑定；须有已验证 DID 的精确 URL 回链、元数据摘要、获准密钥集与实际签名密钥的持有证明。 |
| AUTHZ-79 | `did_bound` 中，`anp_oauth_keys` 非空且引用当前 DID `authentication` 中的方法；按公钥材料匹配实际 JWKS 签名密钥。不透明或 DID 形式的 `kid` 均不能绕过该检查，也不因字符串形式获得权限。 |
| AUTHZ-80 | 使用 `jwks_uri` 时，有效 CIMD 摘要固定的是 URI，不是该 URI 当前返回的字节；`did_bound` 中，即使 CIMD 摘要有效，外部签名密钥被替换或未列入授权仍拒绝；同时含 `jwks` 和 `jwks_uri` 的文档也拒绝。 |
| AUTHZ-81 | 已过期或不一致的 CIMD/JWKS/DID 缓存不能满足必需的新鲜绑定检查；`did_bound` 新鲜度上限为 300 秒或适用的更严格限制。发现摘要/密钥变化时使关联快照失效，缓存淘汰不清除停用状态，必需刷新无法完成时拒绝。 |
| AUTHZ-82 | 必需的 `did_bound` 检查失败，或 AS 缺少声明能力：停止，不改用 `cimd`、更换 client_id 或降低认证强度。声明 `anp_cimd_binding` 的 AS 对缺少必需绑定的客户端拒绝；客户端选择退出或省略发现提示均不能绕过强制检查。只有客户端与 AS 策略都允许时，才可在流程前选定 `cimd`。 |
| AUTHZ-83 | 同一 DID 改为指向新的 CIMD URL：按新的 OAuth 客户端处理，不继承旧 consent、授权码或刷新令牌；URL 保持不变但关联 DID 改变时，也须按策略重新评审绑定与授权。 |

## 场景标识维护

场景标识是稳定证据引用，不是必须连续的清单序号。已退役的 03、19、24、25、28、34–40，以及 0.6 退役的 51、52、58 均不复用。0.4 新增要求从 41 开始，0.5 的 VC 场景从 51 开始（角色凭证为 61–64），0.6 新增的直接出示场景为 65–75。0.7 保留这些 VC 场景不变，按 URL 客户端身份和模式相关检查更新已有 OAuth 场景，新增 CIMD/绑定场景 76–83。编号空缺不免除表中任何场景；证据除场景 ID 外，还须注明协议修订与选定模式。
